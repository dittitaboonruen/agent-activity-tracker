# Royal Partner — บันทึกยอดรวมรายเดือน

## ขั้นตอนทำงาน

ระบบนี้ใช้กรอกยอดรวมทั้งเดือน เดือนละครั้ง ทั้งนำส่งและอนุมัติ ไม่ได้ใช้บันทึกแต่ละวัน

1. เปิด `/admin/production` เลือกเดือน/ปี แล้วเลือก **รายบุคคล / รายหน่วย**
2. กรอกหรือวางจาก Excel แยกกลุ่ม **ผลงานเดือนนี้ / สะสม YTD / EXP–LAP–LIMRA / PA**
3. บันทึกร่าง ตรวจยอด แล้ว **ยืนยันยอดของเดือนนั้น** รายบุคคลและรายหน่วยแยกกัน
4. เปิด `/dashboard/performance` เลือกเดือนและระดับข้อมูล เพื่อดูรายงานหรือส่งออก

ไม่ต้องเลือกวันที่รายวัน ไม่ต้องกรอกยอดซ้ำสองระบบ และไม่ต้องสลับแหล่งข้อมูลรายวัน/สิ้นเดือน
ระบบบันทึกแต่ละวันใหม่จะสร้างแยกภายหลัง ไม่เชื่อมยอดเข้ากับระบบรายเดือนนี้โดยอัตโนมัติ

## ข้อมูลที่กรอก

| กลุ่ม | ช่องตัวเลข |
|---|---|
| เดือนนี้ | Case นำส่ง/อนุมัติ, FYP นำส่ง/อนุมัติ, FYC อนุมัติ |
| YTD | Case/FYP/FYC สะสมตามรายงาน AIA |
| Persistency | EXP/LAP/LIMRA ตามรายงาน AIA ของเดือนนั้น |
| PA | Case/FYP/FYC รวมเดือนนี้ และ PA Case/FYP/FYC YTD |

Active Agent รายหน่วย, Approved Months รายบุคคล และหมายเหตุเป็นช่องเพิ่มเติมที่ไม่บังคับ
ช่องว่างหมายถึงยังไม่มีข้อมูล ศูนย์ต้องกรอก 0; ยืนยันยอดเมื่อกรอกตัวเลขหลักครบทุกกลุ่ม
YTD เป็นยอดสะสมที่กรอกโดยตรง ไม่บวก YTD แต่ละเดือนเข้าด้วยกัน; LIMRA ไม่เฉลี่ยรวม

วางจาก Excel: คัดลอกรหัสเป็นคอลัมน์แรก ตามด้วยตัวเลขตามหัวตารางของกลุ่มที่เลือก ไม่รวมหัวตาราง
ระบบจับคู่ด้วยรหัส ไม่ต้องเรียงแถว และปฏิเสธรหัสซ้ำ/รหัสไม่อยู่ในทะเบียน

## ติดตั้งหรืออัปเดตฐานข้อมูล — ใช้ไฟล์เดียว

เปิด SQL Editor ของ Supabase โปรเจกต์ **Agent Tracking** แล้วรันทั้งไฟล์:

`supabase/INSTALL_MONTHLY_PRODUCTION.sql`

ไฟล์นี้รวมการติดตั้งเดิมกับการเพิ่มช่องนำส่ง/PA/หมายเหตุแล้ว ใช้ได้ทั้งฐานที่ยังไม่เคยติดตั้ง และฐานที่รัน SQL เวอร์ชันก่อนหน้าไปแล้ว รันซ้ำได้
ไม่ลบ ไม่ย้าย และไม่นำข้อมูล `daily_production` เดิมมารวมยอดใหม่

ตรวจหลังติดตั้ง:

```sql
select column_name from information_schema.columns
where table_schema='public' and table_name='aia_monthly_rows'
and column_name in ('month_cases_submitted','month_fyp_submitted',
 'month_pa_cases','month_pa_fyp','month_pa_fyc',
 'ytd_pa_cases','ytd_pa_fyp','ytd_pa_fyc','approved_months','note')
order by column_name;
```

ต้องได้ครบ 10 แถว จากนั้นรีเฟรชหน้ากรอก ลองบันทึกฉบับร่างและโหลดกลับก่อนยืนยันยอดจริง
ฐานเวอร์ชันเก่าจะปิดปุ่มบันทึกเพื่อป้องกันช่องนำส่งและ PA ถูกทิ้งโดยไม่แจ้ง

## ข้อมูลเก่าและรายงาน

- หน้ารายงานมี **ดูข้อมูลเดิมก่อนปรับระบบ** สำหรับเปิดตาราง/กราฟเดิมย้อนหลังเท่านั้น
- หน้ากรอกรายวันเดิมถูกนำออก และ API เขียนข้อมูลเก่าตอบ 410 เพื่อรักษาประวัติ
- Snapshot AIA เวอร์ชันก่อนหน้าคงตัวเลขและสถานะเดิม ช่องที่เพิ่มใหม่เป็น NULL และแสดง — จนกว่าจะเปิดแก้ไขและยืนยันใหม่
- รายงานใหม่อ่านนำส่ง อนุมัติ YTD และ PA จาก snapshot เดือนเดียวกัน ไม่อ่านข้อมูลรายวันมาผสม
- เลือกดูเดือนนี้/YTD/Persistency/PA/ทุกคอลัมน์; CSV ที่เปิดด้วย Excel และ PDF ส่งออกครบทุกกลุ่ม รวมหมายเหตุ
- การแก้ยอดยืนยันต้องเปิดแก้ไขก่อน มี revision ป้องกันการบันทึกทับกัน และ audit เก็บก่อน/หลังพร้อมผู้แก้ไข
- คงสิทธิ์จัดการผลงานและดูรายงานเดิม ไม่เปิดตารางให้ anon/authenticated อ่านเขียนโดยตรง

## ตรวจสอบโค้ด

```text
node_modules/.bin/tsc --noEmit
node --test tests/aia-monthly.test.cjs tests/aia-monthly-api.test.cjs
node --test tests/aia-monthly-sql.cjs
npm run build
```

SQL test ต้องมี `@electric-sql/pglite` ในสภาพแวดล้อมทดสอบ ครอบคลุมติดตั้งใหม่/อัปเกรดเดิม/รันซ้ำ, ช่องนำส่งและ PA, rollback, revision, RLS, audit และรักษาข้อมูลเก่า
การบันทึกกับฐานจริงต้องทดสอบหลังผู้ดูแลรัน SQL ใน Agent Tracking เพราะการเชื่อมต่อฐานข้อมูลในเซสชันนี้ยังเข้าไม่ถึงโปรเจกต์ดังกล่าว
