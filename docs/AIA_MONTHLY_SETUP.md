# Royal Partner — เปิดใช้ยอด AIA สิ้นเดือน

## สิ่งที่เปลี่ยน

- หน้ากรอก `/admin/production` และหน้ารายงาน `/dashboard/performance` แยกกันเหมือนเดิม
- รายวันยังเก็บทุกช่องเดิม รวมหมายเหตุและ PA เลือกดู นำส่ง / อนุมัติ / PA / ทุกคอลัมน์
- เพิ่มปิดยอด AIA รายเดือนทั้งรายบุคคลและรายหน่วย ยืนยันสถานะแยกกัน
- กรอก Cases/FYP/FYC เดือนนี้, Cases/FYP/FYC YTD, EXP/LAP/LIMRA และ Active Agent รายหน่วยถ้ามี
- วางข้อมูล Excel แบบ TSV: รหัสก่อน ตามด้วยตัวเลขตามหัวตาราง จับคู่ด้วยรหัส ไม่จับคู่ด้วยชื่อ
- ช่องว่างหมายถึงไม่มีข้อมูล; ศูนย์ต้องกรอก 0; ค่าปรับลดลงได้ โดยเก็บแยกเดือน
- Monthly Performance เปิดด้วยข้อมูลรายวันเหมือนเดิม มีโหมดยอดยืนยัน AIA เพิ่มเติม
- ทุกคอลัมน์เดิมยังดูได้; กราฟเดิม อันดับเครือ และ PDF เดิมอยู่ในโหมดรายวัน
- AIA อนุมัติ/YTD/EXP/LAP/LIMRA ใช้ยอดยืนยันโดยตรง นำส่ง/PA/Approved Months แสดงแหล่งข้อมูลรายวันกำกับ
- โหมด AIA ส่งออก Excel-compatible CSV (UTF-8 BOM) และพิมพ์ PDF แบบแยกกลุ่มข้อมูล ส่งออกครบทุกกลุ่ม
- แก้การดึงรายวันให้แบ่งหน้า เพื่อไม่ให้ YTD ขาดเมื่อเกินขีดจำกัดต่อคำขอ

## ขั้นตอนเปิดใช้งานฐานข้อมูล

1. เปิด Supabase โปรเจกต์ **Agent Tracking** ที่ระบบ production ใช้อยู่
2. เปิด SQL Editor วาง SQL ทั้งไฟล์ `supabase/migrations/20261104061040_aia_monthly_snapshots.sql` แล้ว Run ทั้งชุดครั้งเดียว
3. รันคำสั่งตรวจต่อไปนี้ ต้องเห็นชื่อตารางครบสามรายการและฟังก์ชันหนึ่งรายการ

```sql
select to_regclass('public.aia_monthly_batches') as batches,
       to_regclass('public.aia_monthly_rows') as rows,
       to_regclass('public.aia_monthly_audit') as audit,
       to_regprocedure('public.save_aia_monthly_batch(integer,integer,text,date,text,integer,jsonb,uuid)') as save_function;
```

4. รีเฟรชหน้ากรอก เลือก **ปิดยอด AIA สิ้นเดือน** แล้วเลือกเดือนและระดับข้อมูล
5. ทดสอบ **บันทึกฉบับร่าง** และรีเฟรช ตรวจว่าค่ากลับมาเหมือนที่บันทึก ก่อนยืนยันยอดจริง
6. ยืนยันรายบุคคลและรายหน่วยแยกกัน แล้วเปิด Monthly Performance เลือก **ยอดยืนยัน AIA** ตรวจยอดและส่งออก

ยังไม่รัน SQL: ระบบรายวันยังใช้งานได้ ส่วนยอด AIA จะแจ้งว่ายังไม่เปิดใช้งานและปิดปุ่มบันทึก

## วิธีใช้สั้น ๆ

ระหว่างเดือน: บันทึกรายวัน → เลือกวันที่ → กรอกช่องเดิม → บันทึก

สิ้นเดือน: เลือกเดือน → รายบุคคล → วางยอดเดือนนี้/YTD/EXP-LAP-LIMRA → ตรวจและยืนยัน → รายหน่วย → วางยอดจาก AIA → ตรวจและยืนยัน

รายงาน: เลือกเดือน → แหล่งข้อมูล → รายบุคคล/รายหน่วย → เลือกกลุ่มคอลัมน์หรือทุกคอลัมน์ → Excel (CSV) / Export PDF

แก้ยอดที่ยืนยันแล้ว: เปิดแก้ไขยอดระดับนั้น → แก้ไข → ยืนยันใหม่ การเปิดแก้ไขทำให้รายงาน AIA ระดับนั้นรอยืนยันชั่วคราว เก็บประวัติและค่าก่อน/หลังทุกครั้ง

## ความถูกต้องและสิทธิ์

- ไม่แก้ ไม่ย้าย ไม่ลบข้อมูล `daily_production` เดิม
- ไม่บวก YTD ข้ามเดือน ไม่เฉลี่ย LIMRA และไม่บวกยอดหน่วยซ้ำกับรายบุคคล
- เก็บชื่อ/รหัส/หน่วยใน snapshot ของเดือนนั้นเพื่อคงประวัติ
- ข้อมูลอ้างอิงรายวันระดับหน่วยจัดตามทะเบียนตัวแทนปัจจุบัน; ยอดหน่วย AIA เป็นยอดที่กรอกโดยตรง
- ข้อมูลรายบุคคล/รายหน่วยมี revision คนละชุด หากมีคนบันทึกไปก่อน ระบบตอบ 409 ให้โหลดใหม่
- ผู้จัดการยอดใช้สิทธิ์เดิม `can_manage_daily_production`; ผู้ดูรายงานใช้ `can_view_monthly_performance`
- ตารางใหม่เปิด RLS และไม่ให้ anon/authenticated อ่านเขียนโดยตรง ใช้ server routes ที่ตรวจสิทธิ์แล้วเท่านั้น
- ฟังก์ชันบันทึกเป็น SECURITY INVOKER เรียกได้เฉพาะ service_role; บันทึกทั้งชุดใน transaction และเก็บ actor จาก session

## การตรวจสอบก่อนปล่อย

- TypeScript: `node_modules/.bin/tsc --noEmit`
- Logic/API: `node --test tests/aia-monthly.test.cjs tests/aia-monthly-api.test.cjs`
- SQL: เมื่อติดตั้ง `@electric-sql/pglite` ในสภาพแวดล้อมทดสอบแล้ว ให้รัน `node --test tests/aia-monthly-sql.cjs`
- Production build: `npm run build`
- ตรวจ permission, rollback, snapshot เดือนก่อน, สอง scope, revision, RLS และ audit ด้วย PostgreSQL-compatible PGlite

การตรวจฐานข้อมูลจริงและหน้าจอหลังเข้าสู่ระบบต้องทำหลังรัน SQL ในโปรเจกต์ Agent Tracking; การเชื่อมต่อฐานข้อมูลที่มีในเซสชันนี้ไม่เห็นโปรเจกต์ดังกล่าว
